# WinGlow 3.2.3 本地验收记录

日期：2026-10-03。本地测试版，未发布公共 GitHub Release。

## 修复与依据

用户实机发现 TranslucentTB 在资源管理器连续重启后报错退出。官方 2026.2 ResetState 对30秒内的连续 Explorer PID 变化有阻塞警告与退出保护。旧版在 Explorer 刷新后才重启组件，处理时机过晚。

- 刷新前暂停 WinGlow 自有 TranslucentTB，配置保存为精确原字节；刷新后确认桌面和主任务栏同 PID，并连续稳定2秒再启动已启用的效果。
- Windows 自动恢复 Shell 获得2秒优先机会；仅必要时启动已预先准备的普通权限备用 Explorer。
- 正常退出无响应超过4秒时，重新核验指定进程句柄的完整 EXE 路径，再结束独立组件；不结束其他来源实例。不修改上游保护或官方二进制。
- 刷新失败仍尝试恢复；恢复失败不标记观察完成，允许后台有限重试。
- 外部 Explorer PID 变化也按暂停、稳定等待、同步处理；仍仅在 WinGlow 运行期间保护。

## 验证

- 51项默认 Rust 测试通过，另1项实机测试默认忽略；fmt、Clippy all-targets -D warnings、TypeScript/Vite 均通过。
- 生命周期回归覆盖暂停先于 Shell、暂停失败不重启 Shell、Shell 失败仍恢复。
- 稳定性回归覆盖 PID/HWND 改变或任务栏消失均重置稳定计时。
- 第一次显式实机测试发现旧报错实例不能正常退出，测试失败后补充精确来源核验的异常退出处理；没有把这次失败记为成功。
- 完整修复后的显式实机测试在14.41秒内连续刷新两次：每次 Shell PID 实际改变，自有任务栏组件仍运行，没有自有可见标准警告对话框，配置逐字节一致，已启用 Breeze 仍运行。完成后额外等待3秒再次检查。
- 测试持有全局优化锁，未重新应用字体、菜单精简或一键优化，不写入新的系统设置；只刷新桌面并恢复之前已启用的运行态。

## 实机边界

该测试证明这台电脑上通过 WinGlow 协调的连续刷新与组件恢复通过，不等于对其他电脑、所有第三方冲突、外部程序造成的极快重启或长期运行作保证。任务栏运行与无警告窗口由原生 API 检查；最终视觉观感由用户验收。WinGlow 退出后不提供后台服务保护，官方组件自身保护仍有效。
