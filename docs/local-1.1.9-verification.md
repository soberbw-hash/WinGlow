# 1.1.9 本地验收版

本版本仅生成本地安装包，未经用户确认不得推送或发布。

## 本次调整

- 首页删除整块可展开的效果设置；任务栏、窗口背景和开始菜单参数仍在「基础美化」。
- 一键优化启用 WinGlow 的三组动态桌面场景：夜色、海色、晨光，每五分钟切换一次，柔和过渡，默认静音。
- 轮播在 Lively 的网页壁纸内完成，关闭 WinGlow 后仍能继续。它不遍历用户自行导入的 Lively 壁纸。
- 已优化的旧版本首次打开新版本时，按新默认方案更新受管理的设置；未优化的用户不自动启用。相同版本不重复更新。
- 更新沿用第一次优化前的备份，通过交易记录链恢复。菜单精简继续只减不加，不重新开启用户手动隐藏的菜单。
- 安装包携带独立 ICO，已有桌面快捷方式使用实际安装目录内的图标路径。本机旧快捷方式的路径已纠正并发送图标刷新通知。

## 内部设置接入

- 「基础美化」中的透明任务栏直接提供材质、颜色、浓度和细线，以及窗口最大化、开始菜单打开时的独立效果。仅重新加载 WinGlow 的任务栏组件，使用原交易备份与回退机制，不重启资源管理器。修改时保留未编辑的应用规则与参数。
- 动态壁纸提供内置场景色板、已有 Lively 库的缩略图、选择和应用、轮播间隔、视频/GIF 导入、暂停/继续、持久化音量和恢复上次修改。库目录下的项目才可选择；不接受任意路径作为项目标识。
- 经典布局提供系统/经典任务栏、图标对齐、按钮合并、小图标、系统/经典开始菜单。参数先自动备份再写入，注销后生效，不主动重启资源管理器。
- 经典任务栏与 WinGlow 的透明效果避免同时启用；经典开始菜单和 Windhawk 开始菜单美化避免同时控制。已有其他组件实例仍按原来源检查处理。
- 系统构建不在当前接入范围时，前端禁用经典布局参数，后端拒绝调用，保留「恢复系统任务栏」。安装、打开和内部应用均做兼容性检查。官方支持范围与 WinGlow 实际放行范围分别说明，不把官方测试其他 28000 小版本当作本机通过验收。
- 核对官方 [TranslucentTB 配置](https://github.com/TranslucentTB/TranslucentTB.github.io/blob/master/config.md)、[Lively 命令](https://github.com/lively-community/lively/wiki/Command-Line-Controls)、[ExplorerPatcher 参数](https://github.com/valinet/ExplorerPatcher/blob/master/ep_gui/resources/settings.reg)。组件保持独立、未经修改；仅在 WinGlow 内提供常用设置界面。

内部接入验收：89 项自动测试通过，3 项专门环境测试未运行；严格 Clippy 通过。浏览器 IPC 验证覆盖 760×600、1707×960、2560×1440 的参数应用和无横向溢出；模拟支持和不支持系统两种经典布局入口状态。

实际壁纸验收连续选择夜色和海色，保存音量 10%，恢复上次配置，再恢复整个验证开始前的壁纸与运行状态。应用和恢复均通过；任务栏配置未被壁纸操作改动，没有重启资源管理器，未实际启用 ExplorerPatcher。发现 Lively 2.2.1 的 CLI 音量不持久化，改成备份后停下自身组件、保存固定音量字段再加载原壁纸，复测通过。

## 重启后字号缩小修复

实测 AppliedDPI=144；最早原始备份的六类 WindowMetrics 字体高度均为 -18，旧版保存为 -12。ui_fonts::entries 错误地将实时字体统一缩放到 96 DPI。删除这次缩放，持久记录与实时字号一致；192 DPI 回归测试要求 -24 保持 -24。四项 UI 字体测试通过。
本机从最早备份恢复六类字号/字宽，保留当前鸿蒙字体名称和字重；保存修复前值到 WindowsFontTuner/font-size-repair-before.json。通过 SystemParametersInfoW 更新当前非客户区及桌面文字，未重启 Explorer。重启后目视效果仍待用户验收。仍需安装重新打包的测试版本，旧版继续应用字体可能再写入错误字号。
补充实测：SPI_SET 需要 96 DPI 逻辑字号，WindowMetrics 则保存实际字号。同步修正 write 的 API 参数缩放，防止实时应用后先放大、重登后又缩小。修复后 --diagnose-ui-fonts 回读六类实时字体均为 -18/systemDpi=144，与持久记录 -18 一致。

## 2K、4K 与缩放回归

后续实机反馈更正：此版本对 SPI_SET 的 96 DPI 单位假设错误，实际原生 System-aware 写入会缩小并导致回退失败。见 local-1.1.10-verification.md 的实机修复证据；以下自动矩阵不能作为真实原生写入通过的证明。

- 字体 API 的逻辑单位转换抽成生产代码共用函数，测试覆盖 DPI 96/120/144/168/192/216/240/288（100%～300%），六类不同用户字号和字宽、两种字重、重复应用以及旧快照恢复。四项字体测试和严格 Clippy 通过。
- 首页浏览器测试覆盖 2560×1440、3840×2160 各八档缩放对应的逻辑可用空间，加两种窗口大小，共 36 种优化前后场景。对齐、按钮等尺寸、无横向溢出、首页展开区域已删除均通过。此测试模拟可用空间，不代表真实显示器 DPI 事件验收。
- 核对锁定的 tao 0.37.1 框架代码，窗口默认采用 Per-Monitor V2 DPI 感知；字体读写的临时线程 DPI 上下文完成后恢复。未额外叠加网页缩放或改动用户的系统显示缩放。
- 本机实时 DPI=144 的字号回读已验证；实体 2K/4K 双屏切换、系统缩放切换和重启后的目视效果仍待验收。继续保留本地 1.1.9 测试包，不发布。
