# 1.1.12 本地菜单与壁纸开关修复

2026-10-11。未发布、未推送 GitHub。保持版本 1.1.12，避免这次局部修复触发整套优化方案迁移。当前安装器位于 `artifacts/WinGlow-1.1.12-local-menu`，桌面和开始菜单快捷方式已核对到本次安装程序的真实文件路径。

## 已确认的问题与修改

- 菜单切换、一键精简及菜单还原原来被当作必须刷新 Explorer 的操作；集中刷新会暂停 Lively 并重建桌面，所以壁纸会暂时消失。这三类操作现在不重启 Explorer。重复相同设置也不创建新的菜单事务。
- 本机另外有真实 Explorer 崩溃：20:33、20:37、20:39 的 Application 1000 记录为 `ucrtbase.dll` 的 `0xc0000409`。本地转储中的栈地址候选涉及 Breeze `shell.dll`。没有符号化调用栈，不能把所有崩溃认定为同一原因。
- Breeze 0.1.34 的脚本监听会在 `.js` 更新时重建 QuickJS。之前每个开关都改写过滤脚本；现在可执行脚本保持不变，规则改为独立 JSON，在打开菜单时读取。数据损坏保留上一次有效规则，规则与脚本仍参与备份及还原。
- 菜单还原不再包含 `WinGlow-Lively` 等其他类目的启动项。恢复菜单不会关闭壁纸或其他美化。
- 原子替换设置文件时，短暂文件占用原来可导致写入失败、回退又失败。对 Windows 5/32/33 错误有界重试 750ms，保持原子替换，不先删除目标文件、不修改权限。
- Explorer 刷新后的组件恢复分别执行；其中一个恢复失败也不会跳过壁纸恢复。轮播宿主在暂停/恢复期间保留播放意图，停止引擎时不强行拉起用户手动关闭的引擎。
- 主界面启动时同步已启用但退出的自有 Breeze 实例，不要求用户再次开关，也不重启 Explorer。
- 动态壁纸使用与其他功能相同的拨杆。勾选依据实际引擎及播放选择，安装状态不等于开启状态。关闭保存选择并停用，重新开启恢复之前选择，保留安装与壁纸库。手动选择图片仍直接应用。

## 验证

- Rust 108 项测试：104 通过，4 项明确要求设备刷新或安装环境的测试跳过，0 失败；格式与严格 Clippy 通过。生产 TypeScript、Vite、Rust、NSIS 构建通过。
- 菜单 JS fixture 通过压缩/解压、GPU/云盘/微信显示别名、手动重新开启、懒加载子菜单、数据更新与损坏规则场景。
- 壁纸拨杆浏览器 fixture 在 1024×720、1707×960、2560×1440、3840×2160 上检查开启→关闭→开启及实际 IPC 请求；只有主滚动区，无页面外空白和嵌套滚动。浏览器 fixture 不代表原生壁纸渲染。
- 本机原生壁纸关闭→重新开启验收通过，Explorer PID 保持 41160；Lively 因恢复播放配置重新启动，关闭没有卸载引擎。
- Breeze 21460 已实际运行时，原生 WorkBuddy 菜单项开启→关闭→重复关闭，随后一键精简三次；安装版再次重复同样验收。两轮期间 Explorer 41160、Lively 30344、播放器 39800 始终保持，桌面字体、壁纸选择、任务栏、窗口材质、开始菜单配置及相关启动项完全一致。原菜单项状态精确恢复。
- 上述原生验收证明菜单写入不重建桌面；菜单过滤的具体视觉结果由 JS fixture 覆盖，没有在这轮自动验收中操作 Explorer 的实际弹出菜单。
- Breeze 启动后的有界观察未见新的 Explorer Application 1000 崩溃，不能据此保证第三方组件不存在其他崩溃。
- 签名及可信注释验证、四项 SHA256 核对通过；静默安装返回 0。安装程序与便携程序在归一化 Tauri bundle marker 后逐字节一致。安装主程序 SHA256：`1ee6eefb5d5c8b7a79c1ea361520af95d8685526ce177bcbf58bc0dd66f76864`。
- 安装主界面已打开，截图确认首页已优化、无错误条和旧折叠区，桌面仍有动态背景。未执行完整一键优化，未改字号、缩放、UAC，未重启系统或 Explorer。
