# WinGlow 1.1.2 菜单修复

2026-10-10。

用户反馈扩展开关为关闭但旧 Explorer 的文件夹菜单仍有夸克、百度、WorkBuddy 和 Defender 扫描。旧实现仅写 Shell Extensions/Blocked 并发送关联变化通知，没有直接停用各菜单注册引用，也没有刷新已加载扩展的 Explorer。新增受限的 MenuHandler 范围，将默认 CLSID 标记停用，覆盖所有扫描到的文件/文件夹注册位置；不删除 COM 注册或关闭 Defender 本身。旧 OFF 状态补全停用引用。每次仍先自动备份，菜单恢复覆盖新范围。

压缩工具不整体精简。过滤新增快捷 ZIP/7z/RAR 命令识别，保留通用“添加到压缩文件/包”和“解压到/解压文件”原生命令，移除额外快捷格式、邮件和重复的 360 子菜单。没有本地压缩扩展的环境不会伪造命令。

## 已完成验证

- Rust 69 项通过，1 项实际桌面双刷新测试按既有规则跳过；新增处理器身份、禁用/启用值、路径边界和原始注册表类型/字节恢复测试。
- JS 过滤测试覆盖 360/CZIP、7-Zip、WinRAR、嵌套菜单、普通文件夹和无压缩入口的菜单；未新增命令。
- 本机通过同一 worker / 事务入口执行菜单精简：23 条修改先备份并回读校验，结果成功，Explorer 完成一次保护刷新。
- 新建诊断对象的原生文件夹、文本、ZIP 菜单未出现夸克、百度、WorkBuddy、Defender 扫描；普通对象具备 360“添加到压缩文件”，ZIP 具备“解压到”。原生诊断不加载 Breeze 的过滤器，因此报告仍有原生压缩附加命令。
- `%USERPROFILE%/.breeze-shell/scripts/WinGlow-ArchiveFilter.js` 已生成。Breeze 日志显示重载脚本，无脚本求值错误；TranslucentTB 和 Breeze 进程在刷新后均运行。
- Clippy `-D warnings`、TypeScript 和 Vite 生产构建通过，签名安装包和便携包生成成功。
- 最终安装包覆盖安装完成，文件版本及产品版本均为 1.1.2；新版界面已重新打开。安装后的原生菜单检查及物理路径管理员 helper 检查通过，后者不修改系统设置。

## 实际显示边界

本机安装 360/CZIP，7-Zip 和 WinRAR 的规则由真实格式的菜单样例验证，未在本机安装两者。Breeze 的渲染菜单还需用户实际右键验收，不能由原生 HMENU 或进程存在推断最终视觉效果。动态菜单内部是原生处理器生成的命令，不伪造内部开关。
