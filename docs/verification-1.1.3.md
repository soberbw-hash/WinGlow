# WinGlow 1.1.3 本地验收

2026-10-10，修复菜单关闭状态与实际显示不一致，并提供明确的美化用途和手动参数。

## 原因与修改

独立普通权限及管理员进程读到相同注册表，排除本次菜单问题由 Codex 文件目录虚拟化直接引起。实际桌面文件夹通过 `CMF_EXPLORE | CMF_CANRENAME | CMF_EXTENDEDVERBS` 查询时不含 WorkBuddy；再加入 `CMF_DISABLEDVERBS` 时会重新出现已经有 LegacyDisable 的 WorkBuddy、ToDesk、微信输入法等。此前 AppData 中的普通查询没有覆盖这条路径。Breeze 0.1.34 的源码另有模拟 Shift 的 Explorer 菜单兼容补丁；这并不证明所有动态扩展残留均来自同一标志。

新增 Breeze 显示前过滤：从实际 OFF 状态和本次修改后的状态生成受限标签规则，处理 WorkBuddy、百度/夸克、Defender 等动态标签与延迟子菜单。开关操作、精简、启用 Breeze 和应用启动同步都使用同一不可变备份事务。不开启隐藏项目，手动开启后解除相应规则；保留已启用同名注册项，云盘无品牌命令仅在两个相关提供者均关闭时过滤。继续保留压缩与解压。仅保留最近一次实际 Breeze 菜单的标签前后快照，不记录所选文件路径。

窗口功能更名“窗口背景”，明确它只设置支持窗口的系统材质，不把所有不透明应用变成磨砂窗口。新增云母/亚克力选择。开始菜单新增背景浓度 20–95%、圆角 0–24 和独立应用按钮，显示背景、圆角、局部鸿蒙字样的用途，不改布局。所有参数经后端范围校验、自动备份、激活失败回退；新后台记录实际应用材质，避免改为云母后还原仍假定亚克力。
