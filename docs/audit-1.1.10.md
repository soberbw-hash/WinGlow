# WinGlow 1.1.10 检查与改进记录

检查日期：2026-10-11。代码基线是已发布的 1.1.9（c33b56f），修复合入现有 1.1.10 本地工作区。本轮不提交、不推送、不发布，也不自动覆盖正在使用的程序。

## 判断

目前最需要改进的是“设置写入、实际生效、失败恢复”三者的一致性。字体与桌面组件已经能集成，但成功状态有几处判断过早，错误恢复和版本识别也容易使用户困惑。继续保留简洁首页，把常用设置留在左侧分类页；优先补足可靠性。

## 已修复

| 问题 | 原因与处理 |
| --- | --- |
| 字体应用报错、连续回退越变越小 | 本地修复保留 System-aware 原生调用，SPI_SET 使用当前系统 DPI 的实际字号，不再错误地换算成 96 DPI 单位。此前已显式完成原生字体切换及三次恢复的严格回读测试。 |
| 改变缩放后恢复被误判失败 | 写入会按当前 DPI 转换，但事务仍比较旧 DPI 的快照字节。现在只对实时 UI 字体按回读 DPI 转换后严格比较；字体、字重、大小等差异仍然报错，普通注册表值继续逐字节核对。 |
| 已撤销优化仍被旧升级错误阻挡 | 首先确认存在完整的旧优化会话且需要迁移，才采用同版本的历史失败报告。没有会话、未完成会话、已经更新的会话不会被旧报告阻止初始化。 |
| 慢响应造成进度轮询重叠 | 初始化、软件更新、扫描修复的轮询限制为每个组件一个在途请求；控制标记跨 effect 重建保留。初始化 IPC 短暂失败继续重试，不提前解锁系统修改。 |
| 更新状态被迟到的旧请求覆盖 | 更新状态请求增加序号，手动检查更新后，先前尚未返回的状态不能覆盖新结果。浏览器测试注入迟到的错误状态并复现、验证修复。 |
| 桌面组件恢复失败不显示 | 以前先标记初始化完成，后恢复视觉组件，失败只写日志。现在等全部恢复流程返回后结束初始化，失败可见；“重试初始化”同时重试迁移和组件恢复。 |
| 不兼容系统无法恢复布局设置 | 不兼容限制仅禁用应用布局参数，恢复布局设置仍可使用。不会因此开放未经验证的 ExplorerPatcher 模式。 |
| 高缩放下窗口最小高度超过可用区域 | 原生 760×600 最小尺寸不适合所有逻辑工作区。启动和 DPI 切换时按显示器工作区约束尺寸及位置，保留正常范围内的用户位置；最大化和全屏不强制调整。 |

此前已加入的一键优化默认值仍保留：TranslucentTB 六种桌面状态均使用 blur、保留细线，五种状态覆盖全部启用；首次内部应用也采用相同基础配置，手动修改保留其它规则。

## 已检查的行为

- 字体：六种 UI 字体角色、字体资源识别、快照验证、DPI 转换、持久化与实时设置、写入失败及回退失败。
- 恢复：保留不存在状态和原始类型；多次升级按新到旧恢复，最终回到初始备份；损坏备份保留并阻止继续叠加修改。
- 右键菜单：手动启用优先，未知项目不批量关闭；360/CZIP、7-Zip、WinRAR 保留实际已有的基础压缩和解压操作，不生成不存在的解压菜单。
- 资源管理器：批量操作统一收尾，失败不刷新；刷新间隔限制、暂停及恢复自有效果、恢复失败单独提示已有自动用例。本轮没有主动重启 Explorer。
- 第三方组件：按实际路径辨识自有运行时，权限与桌面账户校验，已安装外部工具不按进程名强杀；经典布局仍有兼容性限制。
- 壁纸：点击卡片直接应用；内部轮播三场景不依赖远程脚本；导入路径、缩略图预算、实际选择的加载确认和失败恢复有检查。已知白屏 Parallax 示例仍排除，其他第三方项目不宣称全部健康。
- 软件更新：下载来源与版本限制，签名验证完成后才允许安装；“下载完成”与“优化方案迁移完成”是不同状态。
- 界面：首页没有任务栏/窗口/开始菜单的展开区；主页按钮对齐；基础美化单一主滚动区，底部没有外层空白；小窗口及 2K、4K 的逻辑布局矩阵。

## 本机版本与测试包

本轮观察到同时存在两个界面进程：安装路径 `%LOCALAPPDATA%\WinGlow\WinGlow.exe` 的文件版本为 1.1.7；另一份来自先前 1.1.10 便携包。还有无窗口的材质宿主，不能误当成第三个 GUI。旧界面不会因源码修复自动变成新版本。

读取当前原生 UI 字体：六种角色均为 HarmonyOS Sans SC、700、height=-12、systemDpi=144。它说明原生字体名称已设置，不能据此保证桌面已经完整重绘、字号符合用户观感或重启后的显示正确；这次检查未强制更改用户字号、显示缩放或系统 UAC。

正在运行的旧便携文件阻止覆盖，本次测试输出采用独立目录 `artifacts/WinGlow-1.1.10-audit`。安装器、便携包、更新签名和 SHA-256 清单作为本地测试材料；本地 latest.json 不表示 GitHub 已发布此版本。

## 后续建议与新想法

1. **实际效果自检与定向补修。** “已优化”目前主要依据优化记录。可以在设置页显示实际字体回读、组件运行状态及最近失败项；提供“修复缺失效果”，只补没有生效的部分，保留字号、自定义参数和初始备份，不先全部撤销。首页继续只保留核心操作。
2. **单实例与版本识别。** 普通启动发现已有同版本界面时转到已有窗口；版本升级明确区分旧安装版和测试版，避免两个 GUI 同时刷新状态。工作进程和无窗口宿主仍应允许并存。设置页可显示版本和安装位置。
3. **失败按功能说明。** 错误框先说明哪一项没完成、如何恢复，再提供复制诊断信息；详细路径和事务信息收进详情。字体与菜单的核心修改，以及壁纸下载等可选组件，逐步支持独立重试，避免一个下载失败让整个优化无法开始。
4. **小而可靠的壁纸库。** 默认自动轮播只收经过验收的本地项目；加入加载失败回到上张壁纸和资源占用异常提示。第三方网页壁纸先通过资源及播放器兼容检查再加入默认轮播。
5. **减小重复资源与下载量。** 当前九个完整字体同时出现在原生资源和前端预览资源中。可以研究共用资源或小型预览字体，并把签名验证后的更新包缓存到磁盘，关闭软件再打开不重复下载。先验证预览字形和恢复流程，再改打包结构；不要为了缩包省掉系统应用所需字形。

建议顺序是效果自检、单实例/版本识别、简明诊断，再做壁纸库和包体优化。经典布局继续作为有兼容性限制的可选功能，不进入默认一键安装。
